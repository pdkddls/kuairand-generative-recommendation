# ReSID–T5 · KuaiRand 400 万条曝光生成式推荐

ReSID–T5 根据用户观看历史自回归生成下一条长看视频的三级 SID，返回 Top20。物品编码由两部分组成：FAMAE 从交互序列和结构化字段学习物品表示；冻结的 Qwen3-Embedding-4B 离线批量编码视频文案和类目名称。程序按视频 ID 对齐两路向量，在量化前融合，为固定目录构建一套 GAOQ 码表。T5 训练与推理使用同一份映射。

## 400 万条数据的口径

一个样本单位是一次曝光，唯一键是 `(user_id, video_id, time_ms)`。输入可以是已经准备好的 400 万条曝光 CSV，也可以是 KuaiRand-1K 的三份原始日志。如使用原始日志，程序在去重后的事件中用种子 42 无放回抽取恰好 4,000,000 条，再按时间顺序回放。重复键优先保留随机曝光记录。使用已准备好的 CSV 时，去重后的行数必须恰好为 4,000,000。

| 时间区间（按全部曝光排序） | 用途 |
|---|---|
| 最早约 20%，约 80 万条 | 固定目录、训练 FAMAE、计算物品 CTR、构建 SID |
| 随后约 60%，约 240 万条 | 拟合 TIGER、HSTU 和 ReSID–T5，训练 ReSID–T5 长看效用头 |
| 随后约 10%，约 40 万条 | 按验证 NDCG@20 为三个模型分别选择轮次，同分取较早轮次 |
| 最后约 10%，约 40 万条 | 评估三个模型的物品 Top20 |

同一毫秒的事件统一进入同一时间窗口。训练只使用目录内、反馈在训练截止前已可观测的曝光。三个模型均以其中的长看正例学习下一物品；ReSID–T5 的效用头额外使用长看与非长看曝光。各窗口实际曝光数、可训练曝光数、长看正例数、验证和测试查询数都写入 `data.json`。ReSID–T5 默认每轮更新次数为可训练曝光数除以 128 后向上取整。TIGER、HSTU 各自按训练长看正例数除以其批大小后向上取整。验证和测试各按符合条件的用户数计查询数。目录容量、曝光条数和测试分母是三个不同的量。

**固定候选目录。** 从第一窗口中已曝光且有静态资料的物品中，按曝光次数取最多 100,000 个，次数相同按原始视频 ID 排序。验证和测试各取每位符合条件用户在该窗口内最后一个长看目标；验证标签也须在验证结束前可观测。同一用户有同毫秒多个正例时取原始视频 ID 较大者。目录外目标保留在指标分母中，计为未命中。

**时序特征。** 每个请求只取同用户严格早于请求时刻的最近 16 个目录内曝光。用曝光时刻加向上取整的播放时长估计反馈可观测时刻。历史中尚未结束的播放标记为反馈未知。24 小时热度只统计请求前已完成的长看，ReSID–T5 在训练和推理时均使用此先验。三个模型都能读取截至请求时刻的目录内观看历史，测试时固定模型权重和物品映射。

## 物品表征与 SID

1. **学习交互表征。** FAMAE 为本项目的适配实现，采用轻量字段掩码自编码器。首个窗口中、截止前已完成的目录内长看作为目标，同用户严格在目标之前的最近 16 次目录内曝光作为历史。物品 ID 与可用的作者、视频类型、时长桶、标签及各级类目 ID 等可用字段各有嵌入表。逗号分隔的标签逐项去重，同一标签跨视频共享嵌入，视频的标签字段取有效标签嵌入的均值。遮住该字段时，对全部真实标签计算等权重建损失。空值、UNKNOWN、-1、-124 及其小数形式按缺失处理。训练时随机遮住目标的一个或多个已知字段，双向 Transformer 根据历史和可见字段恢复被遮字段。每个字段 32 维，2 层、4 头，AdamW 学习率 0.001，batch 256，3 轮；大词表每个目标采样 128 个负类。导出每个视频时拼接其静态字段嵌入，同一视频始终对应同一向量。
2. **批量编码视频内容。** 使用静态视频表的标题、描述等文本，支持按官方视频 ID 关联补充表的 `caption`、`show_cover_text` 与分级中文类目名。程序对去重后的有效文本按批次 32 编码，取 Qwen 最后一个有效 token 表示的前 256 维并归一化。没有有效内容的视频保留在目录中，其 Qwen 分支取零。整个目录均缺少文本时，准备阶段提示补齐输入。补充表中缺失或占位的字段保留主表原有的有效值。各补充文件匹配数、有自由文本的视频数、只有类目名的视频数见 `data.json`。
3. **融合与量化。** 两路向量按目录中的视频 ID 对齐，各自做 L2 归一化，然后等权拼接并再次归一化。只有类目名的视频也采用该固定权重；完全缺少文本的视频仅保留字段向量。前两级均按父组做容量平衡的 K-means，每级最多 64 个子组；项目使用按最佳与次佳中心距离差排序的贪心容量分配，最多迭代 10 次。第二级对子中心减去父中心，按余弦相似度用匈牙利算法匹配同层共享的正交锚点。第三级把同一前缀下的物品作为单件叶节点，也按相对父中心的方向一一对齐共享锚点。因此每条三元组可唯一反查固定目录中的视频。
4. **保留效用信息。** 对第一窗口内已完成曝光的点击率，使用全局点击率和 20 次曝光的先验强度平滑，再计算八分位桶。第三级 token 取 `8 × GAOQ 叶码 + CTR 桶`，同一前缀下仍保持唯一。训练记录中的词表按实际使用的 token 紧凑编号。

| 文件 | 用途 |
|---|---|
| `items.csv`、`item_vectors.npy` | 固定目录、对齐后的 Qwen 内容向量；TIGER 读取此内容向量 |
| `famae.pt`、`fused_vectors.npy` | 轻量 FAMAE 权重及字段索引、用于 GAOQ 的融合向量 |
| `quantizer.npz`、`codes.npy` | 固定目录的中心、共享锚点、CTR 边界及最终逐物品三级 SID |
| `semantic.json`、`model.pt` | 编码配置摘要与绑定码表指纹的 T5 检查点；评估时校验视频顺序和 SID |

## 训练与生成

| 配置项 | 最终设置 |
|---|---|
| T5 编码器 / 解码器 | 2 层 / 2 层，隐藏维度 128，4 个注意力头，FFN 512，dropout 0.1 |
| 历史输入 | 每个历史物品 3 个 SID token，叠加反馈与时间间隔嵌入 |
| 生成目标 | 对真实长看物品做教师强制；每层只对目录中合法的子 token 计算交叉熵 |
| 热度先验 | 合法子节点的 logit 加上 log(近 24 小时长看次数 + 0.5 × 该子树物品数)，然后条件归一化 |
| 效用头 | 在三个深度上用解码器隐藏状态及候选 token 预测长看；二元交叉熵权重 0.001，效用梯度在隐藏状态处截断 |
| 训练 | AdamW，学习率 0.0003，权重衰减 0.00001，batch 128，3 轮，裁剪梯度范数 1，seed 42 |
| 生成 | 受合法 SID 前缀树约束的 beam，宽度 200。按「路径累计 log 概率 + 当前层长看概率」剪枝；下一层只继承路径 log 概率，避免同一效用跨层重复计入。默认 SID1 最多 64 个，全部通过；SID2 候选超过 200 时首次剪枝，SID3 选最终 Top20 |

## 数据流程验证

| 验证项 | 检查内容 |
|---|---|
| 400 万条规模检查 | 使用 400 万条构造曝光运行正式数据准备入口，核对去重计数、时间切分和 10 万候选物品目录。 |
| 10 万物品量化检查 | 对 10 万条构造向量运行 GAOQ，检查三级 SID 唯一性及父组容量。 |
| 小规模端到端自检 | 运行 `python check.py`，在 CPU 上使用 480 条构造曝光和小型 Qwen3 检查数据切分、文本关联与缺失回退、FAMAE 和 Qwen 融合、均衡分组、锚点对齐、三级 SID 唯一性、T5 训练与解码，以及基线和生成模型的评估输出。 |

## 基线与评估

[参考对照表](baseline_comparison.md)中，TIGER、HSTU 的 @5 数值引自 KuaiRand-27K 论文，后五项为示例；ReSID–T5 数值由项目提供，历史运行版本与测试查询数待日志核对。对 KuaiRand-1K 的单次运行，测试查询最多 1,000 条，每个 Recall 必须对应同一查询总数下的整数命中数。参考表中 ReSID–T5 的三个 Recall 无法在这一分母范围内同时得到（已考虑保留两位小数）。当前程序在实际运行目录生成同口径评估结果。

三种模型使用同一份 400 万条去重曝光、同一固定目录、同一时间切分和同一组测试查询。每个模型按验证集 NDCG@20 独立选轮，同分取较早轮次。目录外目标计为未命中，所有指标都以全部测试查询为分母。

| 模型 | 如何预测下一件长看物品 |
|---|---|
| TIGER（本项目的适配实现） | 读取 Qwen 内容分支的向量，单独训练 RQ-VAE，使用三级残差码和一个消歧 token标识物品。T5 根据观看历史自回归生成四个 token，在合法目录路径上用 beam search 返回 Top20。 |
| HSTU（本项目的适配实现） | 用物品 ID 序列、相对位置和时间偏置建模观看历史。因果 HSTU 层通过 SiLU 逐点聚合与门控得到请求表示，与全目录物品向量计算点积，选出 Top20。 |
| ReSID–T5 | 用带反馈和时间的历史生成 FAMAE 与 Qwen 融合后的三级效用增强 SID，结合近 24 小时热度先验和长看效用进行受约束解码。 |

两条基线默认隐藏维度 128、4 头、训练 3 轮，训练设置见 `baselines.json`。TIGER 的编码器和解码器各 2 层，RQ-VAE 的三个码本默认各 256 个中心，beam 宽度 200。HSTU 使用 2 层，针对目录内长看目标训练全目录交叉熵。TIGER 与 ReSID–T5 共享冻结的 Qwen 物品向量，各自构建 SID；HSTU 独立学习物品 ID 嵌入。

FAMAE、TIGER 和 HSTU 均为本项目的适配实现。下表列出当前配置文件及代码使用的结构与训练参数。

| 模块 | 当前结构 | 当前训练参数 |
|---|---|---|
| FAMAE | 每字段 32 维；Transformer 编码器 2 层、4 头，FFN 128，dropout 0.1；多标签字段采用共享嵌入均值聚合，导出时拼接各字段嵌入 | AdamW，学习率 0.001，权重衰减 0.00001，batch 256，3 轮，梯度裁剪 1；大词表每目标采样 128 个负类；使用首个时间窗口的已完成长看目标做字段掩码重建 |
| TIGER 的 RQ-VAE | 输入为 256 维 Qwen 向量；编码器 MLP 为 256→128→32，解码器为 32→128→256；三级残差码本，每级最多 256 个 32 维中心；追加一个消歧 token | MiniBatchKMeans 初始化码本；Adam，学习率 0.001，batch 512，15 轮；重建损失、码本损失及权重 0.25 的承诺损失 |
| TIGER 的 T5 | 编码器 / 解码器各 2 层，隐藏维度 128，4 头，FFN 512，dropout 0.1；历史最多 16 个视频，生成四个 token；合法路径 beam 宽度 200 | AdamW，学习率 0.0003，权重衰减 0.00001，batch 128，3 轮，梯度裁剪 1；对训练窗口内长看正例做教师强制和词表交叉熵训练 |
| HSTU | 2 层，隐藏维度 128，4 头，dropout 0.1；U/V/Q/K 投影、SiLU 因果聚合与门控、相对位置偏置及 32 桶时间偏置；历史最多 16 个视频，并追加请求位置；与全目录物品向量计算点积 | AdamW，学习率 0.0003，权重衰减 0.00001，batch 128，3 轮，梯度裁剪 1；对训练窗口内长看正例计算全目录交叉熵 |

FAMAE 和两条基线的默认种子为 42。TIGER、HSTU 分别按验证集 NDCG@20 选择轮次，同分取较早轮次。

`evaluate` 读取三个模型各自的最佳检查点，生成三行对照表 `comparison.md`，包含 Recall 和 NDCG 的 @5、@10、@20，以及 MRR@20。各模型每个 K 的整数命中数、查询数、曝光数、训练正例数、目录规模、精确指标和选用轮次见 `comparison.json`；`test_ranks.csv` 按查询并列保存三个模型的名次，未进 Top20 记为 0。

## 运行

Python 3.11 或 3.12。推荐使用 GPU 离线编码及训练；CPU 模式使用 FP32。先按机器安装相应版本的 PyTorch，再运行以下命令。首次使用默认权重需要能下载 Qwen3-Embedding-4B；已有权重可加 `--model-path /实际的本地模型目录`。运行目录由程序新建。

```bash
python -m pip install -r requirements.txt
python check.py

LOGS=/root/autodl-tmp/KuaiRand-1K/data
EVENTS=/实际路径/kuairand_4m.csv  # 改为本次实验已有的曝光文件
OUT="/root/autodl-tmp/resid_4m_$(date +%Y%m%d_%H%M%S)"
OMP_NUM_THREADS=2 python -u main.py all \
  --events-csv "$EVENTS" --metadata "$LOGS/video_features_basic_1k.csv" \
  --captions "$LOGS/kuairand_video_captions.csv" --categories "$LOGS/kuairand_video_categories.csv" \
  --device cuda:0 --run-dir "$OUT"
cat "$OUT/comparison.md"
```

如需从 KuaiRand-1K 原始日志重新抽样，把 `--events-csv "$EVENTS"` 换成 `--logs "$LOGS"`。两种输入方式可能产生不同的事件集合。新运行在 `data.json` 记录输入方式、是否抽样、实际用户数和排序后曝光记录的 SHA-256，可用于核对实验输入。曝光文件需要 `user_id,video_id,time_ms,long_view,is_click,play_time_ms`，可选 `is_rand`。时间及播放时长均为毫秒。静态物品表按 `video_id` 唯一，使用与官方补充表 `final_video_id` 相同的 KuaiRand 视频 ID。若本地数据重新编号，先恢复两边的对应关系。官方一至四级类目 ID（从 `first_level_category_id` 到 `fourth_level_category_id`）统一映射为 `category1_id` 至 `category4_id`，供 FAMAE 使用，中文类目名进入 Qwen。主表也支持这两种 ID 列名。官方补充表需单独获取；两张表可分别传入，也可以事先将文本列合入静态表后只传 `--metadata`。

[KuaiRand 官方补充视频文案与类目数据](https://zenodo.org/records/18159199)。

原始日志模式预期同目录有 `log_standard_4_08_to_4_21_1k.csv`、`log_standard_4_22_to_5_08_1k.csv`、`log_random_4_22_to_5_08_1k.csv`。

新运行在准备阶段同时保存主配置和基线配置。主模型的层数、宽度、头数等取自 `config.json` 的 `t5` 对象；`baselines.json` 控制 TIGER 和 HSTU。分步运行读取运行目录内的配置。旧运行没有 `t5` 对象时沿用历史结构，缺少基线配置快照时训练基线回退到项目的 `baselines.json`。

分步运行的顺序为 `prepare → encode → train → baselines → evaluate`。当前字段编码版本为 `famae_qwen_gaoq_ctr_v2`。从原始输入重新运行 `prepare` 和 `encode`，在新目录生成 v2 码表。已有 v1 码表可继续训练或评估对应的 T5；评估已训练模型时验证码表指纹。原运行目录可用已有权重和原 SID 重做旧方案评估，结果文件会写明对应的编码方法。已有匹配的 ReSID–T5 检查点和物品向量时，可在对应目录运行以下命令。

```bash
python -u main.py baselines --run-dir "$OUT" --device cuda:0
python -u main.py evaluate --run-dir "$OUT" --device cuda:0
cat "$OUT/comparison.md"
```
